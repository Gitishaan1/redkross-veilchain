# Test data provenance

All data in this repository is **synthetic**. No real person, customer, employee, bank account, credential or system is represented.

| File | Origin | Notes |
|---|---|---|
| `customer_records_synthetic.csv` | Provided by RedKross in the Task 2 starter pack | 6 records. Unmodified (SHA-256 in `evidence/provided_files_sha256.txt`). |
| `redaction_test_cases.csv` | Provided by RedKross in the Task 2 starter pack | 4 cases, RED-01 to RED-04. Unmodified. |
| `../policy/data_classification_policy.json` | Provided by RedKross ("Northstar Synthetic Data Handling Policy") | Unmodified. |
| `synthetic_records_500.csv` | Generated by `scripts/generate_synthetic.py` (seed 1337) | 500 records in the same shape as the provided file. |
| `synthetic_text_corpus.jsonl` | Generated by the same script (seed 1337) | 400 labelled lines (ground-truth spans) used for precision/recall. |

## How the synthetic values are made safe

- **Names:** fictional first names combined with surnames such as "Example", "Dummy", "Sample".
- **Emails:** only the reserved domains `example.com`, `example.net`, `example.org` (RFC 2606), which cannot belong to anyone.
- **Phone numbers:** `+353-00-NNN-NNNN`. The area code `00` does not exist, so the numbers cannot be routed.
- **Card numbers:** the publicly documented payment-processor *test* numbers only.
- **Secrets:** carry the visible marker `VCFAKE` and work nowhere.
- **Private keys:** a key-looking block is assembled in memory by tests and the red-team suite only. It is never written into committed data, so secret scanners are not triggered.

The evaluation corpus is generated by the same code that defines the ground truth, so its scores describe how well the detectors match *these* patterns, not how they would perform on real-world data (see the report's limitations).
